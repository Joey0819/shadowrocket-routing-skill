# 脱敏案例与证据范围

这是 2026-10 的一次本地维护经验，不能代替读取此 Skill 时的当前状态。

## 国内服务恢复

2026-10-15，用户报告 Mac 上 UU 远程、微信公众号文章及多种国内网站无法使用。活动配置已有 qq.com 直连，但普通 DNS 与备用 DNS 依赖境外代理。明确直连域名与 IP 分类触发的解析走不同路径，补一条微信规则不足以消除未覆盖国内域名的解析依赖。

备份后，将普通/直连 DNS 改为国内 DoH，并为该解析连接限定不使用 HTTP/3；备用改用另一国内 DoH。补齐微信、网易配套域名，以及明确代理规则之后的 `.cn` 直连。

国外 AI 优先 PROXY、最终 PROXY、UDP 不支持时 REJECT、选中节点、代理链、端口、订阅、Hosts、重写和系统阻断保持原值。保存读回、编译和活动配置勾选通过；Claude 应用内规则仍匹配 PROXY。

公众号入口 HTTPS 返回 200、UU 官网返回 301，只证明入口响应。**用户随后实际重试并确认 UU 远程与公众号文章「两者都恢复」**，这是实际服务恢复的用户确认，区别于助手直接验证完整远控会话。

本次没有修改 PF 或重复故障抓包，不把网页响应描述为新的断线防泄露验证。

## 历史系统保护验证

此前已有独立 PF 与节点同步服务。一份 IPv4 故障与恢复报告记录 234 个故障/重连样本，选定 AI/测试目标物理出站包为 0，并有正常代理流量及国内物理直连的正向对照。这仅是特定时刻、节点、有限目标与 IPv4 上联的历史证据。

实现、原始配置、抓包、节点快照和完整报告均未公开打包。不能声称「安装 Skill 即获得同样保护」，也不能扩大为全部未来 AI 地址、IPv6 和启动最早阶段均已验证。

## 其他经验

- 过期 Host 固定地址曾使上游超时；恢复动态解析后部分节点恢复，并非所有 timeout 均解决。
- socket 探测曾被 TUN 截获，没有观察到匹配物理包，故连接成功不视为服务器可达的充分证据。
- 同步助手曾出现 AppKit 窗口关闭再打开崩溃，修复生命周期后恢复只读快照。授权父目录会产生结构不明/零节点，需授权精确目录。
- 同步器运行、快照完整、白名单更新、协议可用、应用可访问应分别确认。

## 隐私处理

省略真实出口/节点 IP、端口、订阅链接、账户、设备标识及 tailnet 域名。配置片段只含公共服务域名与公共 DNS 地址。不要据此推断公开仓库作者的当前网络拓扑。
